# Omaha Metro — Ridership Dashboard

**Live at [omahatransitdata.org](https://omahatransitdata.org)** — the canonical URL.
Share this one.

A customizable dashboard of Omaha Metro **fixed-route passenger trips**, built
with custom HTML web components (Lit / lit-html), vanilla JavaScript and pure
CSS. Styling follows ometro.com's palette (Metro blue `#007DBA`, navy `#053955`,
ORBT orange `#E87722`) and type (Mulish + a condensed display face).

## Features

- **View by Day / Month / Year** — granularity toggle. Month and Year are driven
  by the real Board-Packet data; Day activates automatically once daily data is
  imported.
- **Bar, Line, or Table** displays, with **Stacked / Grouped** bars when comparing routes.
- **Year range** filter (2019 → present).
- **Route selection** — compare the official system-wide totals or explore the
  clearly labeled estimated 2026 route series.
- **KPI cards** — total trips, average per period, busiest period, year-over-year.
- **Hover tooltips** with per-route and total values.
- **CSV download** of the current filtered view.
- The data schema and retained importer component are ready for exact route-level
  CSV / JSON data if Metro supplies it later.

## Running

ES modules and `fetch()` require the files to be served over HTTP (not opened as
`file://`). From the project root:

```bash
python3 -m http.server 8000
# then open http://localhost:8000
```

Any static server works (`npx serve`, etc.). Lit is vendored locally
(`vendor/lit.js`) and wired in via an import map, so the site is fully
self-contained — **no build step and no CDN dependency**.

## Deploying

This is a plain static site (HTML/CSS/JS + generated data files, no server, no build), so
it hosts for free on any static host. There is **nothing to build** — the deploy
output *is* the repository root.

### Current deployment

The site runs on **Cloudflare** as a Worker named `metro-ridership-dashboard`,
serving the repo root as static assets.

| Hostname | Behavior |
| --- | --- |
| `omahatransitdata.org` | **Canonical.** Serves the dashboard. |
| `www.omahatransitdata.org` | `301` → apex, path and query preserved. |
| `metro-ridership-dashboard.todd-nichols.workers.dev` | Original URL, still serving. Kept alive until Metro has been pointed at the new domain. |

Note that the deploy configuration lives in the Cloudflare dashboard — there is
no `wrangler.jsonc` in this repo. Adding one would take over that configuration,
and its `name` would have to match the existing Worker exactly.

### Setting this up elsewhere (Cloudflare Pages or Netlify)

1. Push this folder to a GitHub repo (see below).
2. In Cloudflare Pages (or Netlify), "Create project" → connect the repo.
3. Settings:
   - **Build command:** *(leave empty)*
   - **Build output / publish directory:** `/` (the repo root)
4. Deploy. You get a free HTTPS URL (`*.pages.dev` / `*.netlify.app`) in ~30s.
   Every `git push` to `main` auto-publishes a new version, with a unique preview
   URL per change.

To attach a custom domain, add it in the host's **Custom domains** tab and follow
the DNS instructions (SSL is automatic and free).

> Sharing the link? Use **https://omahatransitdata.org** — not the `workers.dev`
> address, and not a `*.pages.dev` / `*.netlify.app` preview URL.

### Manual / drag-and-drop

Netlify also lets you drag the project folder onto the dashboard to deploy

## Data

`data/ridership.json` and `data/ridership.csv` are generated by `scripts/build-data.mjs` from the monthly
figures in the Metro Board Packet ("Fixed-Route Passenger Trips 2019–2026"
chart, July 2026 Updated Board Packet, PDF p. 34). Each year's twelve monthly values are summed and
checked against the chart's printed annual total before being written, so the
numbers are exact, not estimated.

To regenerate:

```bash
node scripts/build-data.mjs
```

### Data schema

```jsonc
{
  "routes": [
    { "id": "system", "name": "All Routes (System Total)", "color": "#007DBA" }
    // { "id": "11", "name": "Route 11", "color": "#00B398" }
    // { "id": "orbt", "name": "ORBT", "color": "#E87722" }
  ],
  "records": [
    { "routeId": "system", "year": 2019, "month": 1, "trips": 246549 }
    // add "day": 1..31 for daily records
  ]
}
```

### Importing route data (CSV)

The importer component is currently not exposed in the dashboard. When it is
re-enabled, it accepts these CSV columns (header row, any order, case-insensitive):

```csv
routeId,routeName,color,year,month,day,trips
11,Route 11,#00B398,2026,1,,18450
orbt,ORBT,#E87722,2026,1,,42310
```

Leave `day` blank for monthly totals. Do not hand-edit the generated datasets;
update their generator scripts instead.


## Notes & next steps

- The Board Packet chart is labeled **fixed-route**, so it excludes paratransit
  (MOBY) and microtransit (MicroFLEX). If you want those, they can be added as
  separate routes/series.
- Daily granularity needs daily data, which the packets don't publish — the UI is
  already wired for it, so importing a daily CSV is all that's required.
