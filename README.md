# Omaha Metro — Ridership Dashboard

A customizable dashboard of Omaha Metro **fixed-route passenger trips**, built
with custom HTML web components (Lit / lit-html), vanilla JavaScript and pure
CSS. Styling follows ometro.com's palette (Metro blue `#007DBA`, navy `#053955`,
ORBT orange `#E87722`) and type (Mulish + a condensed display face).

## Features

- **View by Day / Month / Year** — granularity toggle. Month and Year are driven
  by the real Board-Packet data; Day activates automatically once daily data is
  imported.
- **Bar or Line** charts, with **Stacked / Grouped** bars when comparing routes.
- **Year range** filter (2019 → present).
- **Route selection** — pick one or more routes. Today the dataset is the
  system-wide total; route-level series light up as soon as they're imported.
- **KPI cards** — total trips, average per period, busiest period, year-over-year.
- **Hover tooltips** with per-route and total values.
- **CSV / JSON import** — drop in route-level data (e.g. the export you request
  from the Board) and it merges into the dashboard live.

## Running

ES modules and `fetch()` require the files to be served over HTTP (not opened as
`file://`). From the project root:

```bash
python3 -m http.server 8000
# then open http://localhost:8000
```

Any static server works (`npx serve`, etc.). Lit is vendored locally
(`vendor/lit.js`) and wired in via an import map, so the site is fully
self-contained — **no build step and no CDN dependency**.

## Deploying

This is a plain static site (HTML/CSS/JS + a JSON file, no server, no build), so
it hosts for free on any static host. There is **nothing to build** — the deploy
output *is* the repository root.

### Cloudflare Pages or Netlify (recommended)

1. Push this folder to a GitHub repo (see below).
2. In Cloudflare Pages (or Netlify), "Create project" → connect the repo.
3. Settings:
   - **Build command:** *(leave empty)*
   - **Build output / publish directory:** `/` (the repo root)
4. Deploy. You get a free HTTPS URL (`*.pages.dev` / `*.netlify.app`) in ~30s.
   Every `git push` to `main` auto-publishes a new version, with a unique preview
   URL per change.

To use a custom domain later, add it in the host's **Custom domains** tab and
follow the DNS instructions (SSL is automatic and free).

> No domain yet? Share the free `*.pages.dev` / `*.netlify.app` link — perfect for
> showing the board before buying a domain.

## Data

`data/ridership.json` is generated by `scripts/build-data.mjs` from the monthly
figures in the Metro Board Packet ("Fixed-Route Passenger Trips 2019–2026"
chart, May 2026 packet, p. 28). Each year's twelve monthly values are summed and
checked against the chart's printed annual total before being written, so the
numbers are exact, not estimated.

To regenerate:

```bash
node scripts/build-data.mjs
```

### Data schema

```jsonc
{
  "routes": [
    { "id": "system", "name": "All Routes (System Total)", "color": "#007DBA" }
    // { "id": "11", "name": "Route 11", "color": "#00B398" }
    // { "id": "orbt", "name": "ORBT", "color": "#E87722" }
  ],
  "records": [
    { "routeId": "system", "year": 2019, "month": 1, "trips": 246549 }
    // add "day": 1..31 for daily records
  ]
}
```

### Importing route data (CSV)

Use the **Import data** button (top-right), or edit `data/ridership.json`
directly. CSV columns (header row, any order, case-insensitive):

```csv
routeId,routeName,color,year,month,day,trips
11,Route 11,#00B398,2026,1,,18450
orbt,ORBT,#E87722,2026,1,,42310
```

Leave `day` blank for monthly totals. A starter template is downloadable from the
import panel.

## Project layout

```
index.html                 import map + fonts + <metro-dashboard>
styles/global.css          design tokens (brand palette, type)
data/ridership.json        generated dataset
scripts/build-data.mjs     dataset generator (verifies annual totals)
src/
  app.js                   entry point
  data-store.js            load / normalize / aggregate / summarize (no DOM)
  components/
    metro-dashboard.js     app root — owns state, wires children
    dashboard-controls.js  granularity / chart / year-range / route filters
    stat-cards.js          KPI summary cards
    ridership-chart.js     dependency-free SVG chart (bar/stacked/grouped/line)
    data-import.js         CSV / JSON import
```

## Notes & next steps

- The Board Packet chart is labeled **fixed-route**, so it excludes paratransit
  (MOBY) and microtransit (MicroFLEX). If you want those, they can be added as
  separate routes/series.
- Daily granularity needs daily data, which the packets don't publish — the UI is
  already wired for it, so importing a daily CSV is all that's required.
